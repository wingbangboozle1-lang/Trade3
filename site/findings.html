4. Fees

ItemValueSource
Taker feefees = roundup(M × 0.07 × C × P × (1−P))K6
Maker feefees = roundup(M × 0.0175 × C × P × (1−P)), M defaults to 0 on the general scheduleK6
Rounding"round up" means fee + position cost rounded up to a centicent ($0.0001)K6
When chargedTaker fees only when immediately matched against resting orders; maker fees only when a resting order later trades; no fee to cancelK6
Per-series multipliersNon-Standard Fees table (e.g. KXCPI 1/1, KXFED 1/1, KXBTCY 0/0)K6
Settlement / membershipNo settlement fee, no membership feeK6
Fee precisionTrade fee rounded up to $0.000001; net fee = trade + rounding − rebate, never below $0K7

Worked check against the official General Trading Fees Table: P=$0.50, C=100 → 0.07×100×0.5×0.5 = 1.75 → table says $1.75. P=$0.45, C=100 → 0.07×100×0.45×0.55 = 1.7325 → table says $1.74 (round up to the centicent). P=$0.10, C=100 → 0.07×100×0.1×0.9 = 0.63 → table says $0.63. Three independent rows reconcile, so the formula as implemented is correct.

Important, and easy to get wrong: ticker messages are combined and flushed once per second — intermediate values are never sent, so a 1-second sampling of that channel can miss a spike that the trade channel would show. The alert engine therefore consumes trade as the primary price stream and ticker as the book/volume snapshot, and records which stream each alert came from.

9. Suggestions to make the site more live and interactive

  1. Trade-print tape as the heartbeat. Use the trade channel as the primary

pulse (every print) and ticker for the 1-second snapshot; show both in the header as distinct rates so a user can see when the feed is quiet vs. broken. K19K18 2. Depth-first detail. Because asks are implied (1 − best opposite bid), show a two-column ladder with "cost to buy N" computed from the actual levels, not from the top of book. K5 3. Resolved-event archive that never forgets. market_lifecycle_v2 determined/settled messages are the only live source of YES/NO resolution; persist them so the archive survives restarts. K21 4. Latency honesty. Stamp every alert with the feed timestamp (ts_ms) and the local receive time, and display the difference. If the clock is off by >30 s the authenticated calls will fail anyway. K3 5. Signal-to-noise control. A second chat filtered by the scoring model, with the reason string shown on each card, so the user can audit why a signal was promoted. 6. One-click "why" panel. For each alert: the series' official settlement source links plus configured news feeds, all labelled candidate causes. K12 7. Keyboard-first navigation. 1–5 jump between topics, p pauses the chats, / focuses search; traders keep hands on the keyboard. 8. Explicit data provenance badge. "DEMO FEED · prices may not reflect real markets" on every price, per Kalshi's own warning. K2 9. Paper-vs-live split view. Show the paper portfolio next to the demo account portfolio, never merged, so strategy results cannot be confused with account results. K15K16 10. Cost-aware ROI. Rank signals by expected value after the real fee formula, not by raw price move, because a $0.10 move at $0.50 costs far more in fees than one at $0.05. K6
