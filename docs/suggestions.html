Suggestions — make it more live, more interactive

Ranked improvements, each tied to an official Kalshi page. Items marked (our design) are recommendations, not Kalshi facts. Full detail and evidence IDs live in SUGGESTIONS.md at the repo root; this page is the readable digest. Status is reviewed at every integration pass (last: 2026-11-21).

Priority 1 — make the data truly live

#SuggestionOfficial sourceStatus
1Server-side relay for the WebSocket feed. Public channels (ticker, trade, market_lifecycle_v2) still require a signed handshake, and orderbook_delta is private. A static page cannot hold keys safely — the Node collector (server/) is the intended relay once a demo key exists.Quick Start: WebSockets · API EnvironmentsOpen — needs a demo key (F3)
2Resolution alerts from lifecycle events, not polling. market_lifecycle_v2 emits determined and settled — the natural triggers for the “resolved YES/NO” feed.Market LifecycleOpen — same key requirement
3Poll only what changed. GET /events accepts min_updated_ts to efficiently poll for changes.Get EventsPartly done — paged polling today; delta polling is a drop-in
4Use orderbook depth for the liquidity ladder. GET /markets/{ticker}/orderbook?depth=N (1–100) keeps “contracts available at each price” payloads small.Get Market OrderbookDone — dashboard quotes depth=15
5Show data freshness on every live number. Market reads can be cached for a few seconds — display “as of” timestamps.Get MarketDone — status bar shows the update time

Priority 2 — charts that match what the API can provide

#SuggestionOfficial sourceStatus
6Be explicit about chart resolution. Candlesticks are 1-minute, 1-hour or 1-day only. A “seconds” view can come only from live poll samples or the trade stream, and the chart should label which.Get Market CandlesticksDone — chart labels “candles + live poll points”
7Use trade prints for price-move evidence. GET /markets/trades with min_ts/max_ts (seconds) can mark the exact print that carried a $0.10 move.Get TradesDone — “what may have moved it” tape panel
8Decide whether block trades trigger alerts (our design). Trades carry is_block_trade; make the choice explicit.Get TradesOpen — owner decision
9Label the $0.10 alert rule as ours (our design). The threshold is the brief’s; the detection method (consecutive observed prices, tick-space) is ours and is documented on the Method page.Get MarketDone — Method page + alert rows

Priority 3 — demo account and trading

#SuggestionOfficial sourceStatus
10Never use legacy order endpoints. Legacy /portfolio/orders writes return 410 Gone; V2 is /portfolio/events/orders.Create Order V2Done — client + server use V2 only
11React to fills instead of polling balance. GET /portfolio/balance is rate-limited to ~1/s on lower tiers; the docs recommend reacting to the user-fills channel.Rate LimitsOpen — needs a demo key
12Use the dedicated user host for fills. wss://user-ws.demo.kalshi.co/trade-api/ws/v2 delivers fill/user_orders with lower latency.API EnvironmentsOpen — needs a demo key
13Sign requests correctly. Sign timestamp + METHOD + path without the query string; keep the clock within 30 seconds.Authenticated RequestsDone — kalshi_client.py implements this verbatim

Open questions (never guessed)
