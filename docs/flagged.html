Flagged for review

Nothing on this page blocks the site. It lists the places where a value could not be confirmed from an official source, where a judgement call was unavoidable, or where a Kalshi record contradicts itself. Unconfirmed values are left blank on the site — never filled in by inference.

#ItemWhat is trueWhat is unconfirmed / my callSourceStatus
F1 “Culture” as a topic Kalshi's tag map has no Culture key. It does have Entertainment with tags Music, Awards, Movies, Television, Video games, Music charts, and so on. I mapped Culture → Entertainment. That is a judgement call, not an official mapping. If you meant something narrower (say, music only), it is a one-line change. Live tag map needs your call
F2 Why a contract jumped ≥ $0.10 Kalshi's public API exposes prices, books, trades and settlement sources — no news feed. Causation cannot be established from official sources, so alerts link the API record, the Kalshi page and the settlement source instead of naming a cause. Automated attribution would need a news API and would still be inference. Market data docs unverified by design
F3 Live WebSocket streaming and real demo orders Both are documented and supported; both require an API key, and the WebSocket requires the handshake itself to be signed. A public static page cannot hold a key without exposing it, so the site polls REST and simulates fills. The signing client in the repo is ready; a small relay you run would close the gap. WebSockets · API keys needs your key
F4 “Highest dollar amount” ranking Kalshi returns volume_fp (contracts), open_interest_fp and prices — there is no dollar-volume field. Events are ranked by contracts × last price. Ranking by raw contract count or by open interest would produce a different order, and neither is more “official”. Get Markets approximation
F5 High-ROI screen thresholds The five rules are published in full and applied exactly as documented. Whether those thresholds isolate genuine opportunity is untested. They are an opinion, encoded and labelled as such — not a validated model. Method → ROI screen heuristic
F6 Strategy results Four rules, fixed fill model (buy the ask), settlement from the exchange's result. Results shown are from demo markets, which Kalshi warns may not reflect real markets. Treat them as a test of the plumbing, not evidence of an edge. Demo environment not evidence
F7 Browser access to the Kalshi API (CORS) Kalshi's docs include browser fetch() examples for the public endpoints. Whether a specific network permits the cross-origin call can only be confirmed from that browser. The dashboard reports the failure and the Method page offers a proxy setting rather than pretending data exists. JS fetch examples verify in your browser
F8 KXBOOKERPRIZE — title vs settlement source Kalshi titles the series “who will win the booker prize”. Its only settlement source is nationalbook.org (National Book Awards), and the contract terms file is BOOKERAWARDS.pdf. These are two different prizes. The row is published exactly as the API returns it; which name is correct cannot be settled from the API, so it is left as-is and flagged here. API record Kalshi metadata conflict
F9 KXLINKPERP and KXSOLPERP — no settlement source Both are Crypto series in the live catalogue, but the API returns settlement_sources: null and an empty contract_url. Their settlement source is therefore blank on the topic page — it is not inferred from the title. If these turn out to be perpetuals rather than event contracts, they may not belong in the topic list at all. KXLINKPERP · KXSOLPERP blank — unverified
F10 Sandbox egress restriction during the build The environment this site was built in could reach the Kalshi API only through its page-fetch proxy, not from the shell. Consequence: every API value was read through an official endpoint and pasted from the response, but automated live re-runs of scripts/verify_series.py must happen from an unrestricted machine. The script is included so you can repeat the check in one command. scripts/verify_series.py (in the repo root) environmental

How to resolve any of these

  • F1 — tell me the exact scope for “culture” and I will narrow the category and tags.
  • F2 — provide a news API key (or accept links only) and I will wire attribution with explicit sourcing.
  • F3 — give the relay a home and supply a demo key; streaming and execution follow.
  • F4, F5 — choose the ranking metric and trade the threshold knobs with me.
  • F8, F9 — confirm with Kalshi support which metadata is authoritative before we publish a resolution for those series.

Everything else on the site is traceable to an official document or an API record — see the verification log.
